# Environment Variables (Project)

This document lists all environment variables used by the project, their purpose, recommended examples, and where to set them (Vercel / local).

## Convex (required)
- **CONVEX_API_KEY**: Secret deploy key for Convex cloud. Example: `dev:avid-lark-265|<SECRET>`.
  - Where: Vercel (Production / Preview / Development) — add as a secret. Locally put in `.env.local` (do NOT commit).
  - Secret: Yes

- **CONVEX_DEPLOYMENT**: Convex deployment id. Example: `dev:avid-lark-265`.
  - Where: Vercel or `.env.local` / `.env` for local dev.
  - Secret: No

- **VITE_CONVEX_URL**: Convex HTTP URL for client. Example: `https://avid-lark-265.convex.cloud`.
  - Where: Vercel / `.env.example` / `.env.local`.
  - Secret: No

- **VITE_CONVEX_SITE_URL**: Convex site URL. Example: `https://avid-lark-265.convex.site`.
  - Where: Vercel / `.env.example` / `.env.local`.
  - Secret: No

## Supabase (required for current app)
- **VITE_SUPABASE_URL**: Public Supabase URL used by the browser client.
  - Where: Vercel / `.env.example` / `.env.local`.
  - Secret: No

- **VITE_SUPABASE_ANON_KEY**: Supabase anon key used by the client.
  - Where: Vercel / `.env.example` / `.env.local`.
  - Secret: Yes

- **SUPABASE_URL** and **SUPABASE_ANON_KEY**: Optional server-side equivalents used by API routes and cron jobs.
  - Where: Vercel / `.env.local`.
  - Secret: Yes

- **SUPABASE_SERVICE_ROLE_KEY**: Optional service-role secret used only in server APIs when elevated privileges are needed.
  - Where: Vercel / `.env.local`.
  - Secret: Yes

## App / Business config (optional)
- **VITE_CAPSTONE_SHOP_MOBILE**: Phone number shown in the UI. Example: `9762626246`.
  - Where: Vercel / `.env.example` / `.env.local`.
  - Secret: No

- **VITE_CAPSTONE_PROJECT_SERVICE_FEE**: Extra service fee (numeric). Example: `0` or `50`.
  - Where: Vercel / `.env.example` / `.env.local`.
  - Secret: No

- **VITE_CAPSTONE_COLLEGE_LIST**: Comma-separated allowed colleges. Example: `RIT Library`.
  - Where: Vercel / `.env.example` / `.env.local`.
  - Secret: No

- **VITE_CAPSTONE_FEATURE_ENABLED**: Feature flag. Example: `true` or `false`.
  - Where: Vercel / `.env.example` / `.env.local`.
  - Secret: No

## Payment (only if used)
- **VITE_RAZORPAY_KEY_ID**: Razorpay public key id (if payments used).
  - Where: Vercel (add as secret) / `.env.local` for local dev.
  - Secret: Yes (private keys should be stored only in secrets)

## Vercel / CLI generated
- **VERCEL_OIDC_TOKEN**: Generated by Vercel CLI when linking/deploying. Do not add manually.
  - Where: created by Vercel on `vercel login` / `vercel` and stored in `.env.local` when downloaded by CLI.
  - Secret: Yes (managed by Vercel)

## Recommendations & commands
- Add secret keys in Vercel via the dashboard: Project → Settings → Environment Variables → Add.
- Or use the Vercel CLI from the project root:

```bash
npm exec -- vercel env add CONVEX_API_KEY production
npm exec -- vercel env add CONVEX_API_KEY preview
npm exec -- vercel env add CONVEX_API_KEY development

npm exec -- vercel env add VITE_RAZORPAY_KEY_ID production
```

- Keep `.env.example` committed with non-secret defaults. Keep real secrets in `.env.local` (gitignored) or in Vercel secrets.
- Do NOT commit `CONVEX_API_KEY` or any private keys to the git repo. Ensure `.gitignore` includes `.env` and `.env.local`.
